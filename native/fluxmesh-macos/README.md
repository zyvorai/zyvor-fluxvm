# FluxMesh macOS NetworkExtension

Native `NEPacketTunnelProvider` control bridge for the Phase-4 FluxMesh plan.

The extension:

- reads `macos-tunnel.v1.json` generated by `fluxmesh-agent`;
- configures IPv4 + deterministic ULA IPv6 addresses and included routes;
- scopes DNS to the FluxMesh private suffix;
- moves raw IP packets between `NEPacketTunnelFlow` and a local engine socket.

## Engine socket

The cryptographic tunnel engine is intentionally outside the extension target so it can be upgraded independently. Datagram framing is one family byte (`4` or `6`) followed by one raw IP packet. The helper returns the same framing for packets that should be injected into the utun interface.

The host application sets these `NETunnelProviderProtocol.providerConfiguration` keys:

- `planPath`: app-group path to the FluxMesh plan;
- `engineSocket`: app-group Unix datagram socket for the userspace WireGuard engine.

Apple NetworkExtension entitlements and signing are required. The source is not a substitute for those Apple provisioning steps.
